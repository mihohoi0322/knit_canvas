# Knit Canvas 設計書

更新日: 2026-09-01  
関連資料: [要件定義](./要件定義.md)

## 1. この文書の目的

Knit Canvas の実装に使用する技術、アプリケーション構成、データ構造、主要機能の設計判断を記録する。

要件や受け入れ条件は `要件定義.md` で管理し、この文書では「どのように実現するか」を扱う。

## 2. 技術構成

> 採用する技術を決定したら、選定理由とともに記載する。

| 項目                 | 採用技術                            | 選定理由・補足                                                               |
| -------------------- | ----------------------------------- | ---------------------------------------------------------------------------- |
| アプリケーション種別 | Webアプリ／PWA                      | まずWebでの公開を優先し、オフライン利用とホーム画面への追加にも対応する      |
| 言語                 | TypeScript                          | データ構造と描画処理を型で安全に管理する                                     |
| UIフレームワーク     | React                               | UIの部品化と周辺ライブラリの充実を重視する                                   |
| ビルドツール         | Vite                                | 開発環境が軽量で、PWA構成にも対応しやすい                                    |
| 描画方式             | Canvas                              | 最大200×200の方眼を大量のDOM要素にせず効率よく描画する                       |
| 状態管理             | Zustand                             | 描画データとUI状態を小さく明示的に管理する                                   |
| ローカル保存         | IndexedDB（Dexie.js）               | 自動保存と複数プロジェクトの構造化データを扱う                               |
| ファイル保存         | JSONベースの `.knitcanvas`          | バックアップ、別端末への移動、読み込みに使用する                             |
| PDF・印刷            | ブラウザー印刷                      | MVPではA4印刷と「PDFとして保存」を使用し、直接生成は将来検討する             |
| テスト               | Vitest、Testing Library、Playwright | 単体、UI、E2Eを役割別に検証する                                              |
| コード品質           | ESLint、Prettier                    | 静的検査と書式を統一する                                                     |
| 配布・ホスティング   | GitHub Pages                        | GitHubリポジトリから静的Webアプリを公開し、HTTPSを利用する                   |
| CI/CD                | GitHub Actions                      | mainブランチの更新時にテスト、ビルド、GitHub Pagesへのデプロイを自動実行する |

## 3. 対応環境

- 対象端末: PC、iPadを優先し、スマートフォンでは閲覧と基本操作に対応する
- 対象ブラウザー: Chrome、Safari、Edgeの現行主要バージョン
- 入力方式: マウス、タッチ、Apple Pencil
- オフライン対応: PWAのキャッシュとIndexedDBにより、主要な編集機能をオフラインで利用可能にする
- PWA対応: MVPに含める
- 将来のネイティブ配布: Web版の公開を優先し、安定後にCapacitor等でiOSアプリ化してApp Storeへ展開する

## 4. アーキテクチャ

### 4.1 基本方針

- 方眼データと画面表示を分離する。
- 描画、リピート表示、印刷表示は同じパターンデータを参照する。
- UI固有の状態と、保存対象のプロジェクトデータを分離する。
- 将来の画像変換機能を、手動編集機能から独立して追加できる構造にする。

## 5. データ設計

### 5.1 プロジェクトデータ

```ts
// 技術選定後に、実際の型定義に合わせて更新する。
type PatternProject = {
  name: string
  columns: number
  rows: number
  stitchesPer10cm: number
  rowsPer10cm: number
  palette: YarnColor[]
  cells: Array<string | null>
  repeatCount: 3 | 5 | 8
  createdAt: string
  updatedAt: string
}

type YarnColor = {
  id: string
  name: string
  value: string
}
```

### 5.2 検討事項

- セルを一次元配列または二次元配列のどちらで保持するか
- 方眼サイズ変更時に既存セルを保持する範囲
- セルはCSS色値ではなくパレットIDを参照する。
- 保存データには形式名とバージョンを含め、読み込み時に検証する。

### 5.3 ローカル保存

- 日常的な自動保存にはIndexedDBを使用し、Dexie.jsを介してアクセスする。
- 起動時に前回開いていたプロジェクトを復元する。
- 描画操作のたびに同期保存せず、短い待機時間を設けて変更をまとめて保存する。
- 画面には「保存中」「保存済み」「保存失敗」の状態を表示する。
- IndexedDBはブラウザーデータ削除時に失われる可能性があるため、ファイルへの書き出しも提供する。

### 5.4 プロジェクトファイル

- 拡張子は `.knitcanvas` とし、中身はUTF-8のJSONとする。
- ファイルには `format`、`version`、プロジェクト本体を格納する。
- 読み込み時は形式、バージョン、必須項目、値の範囲を検証する。
- 新しいバージョンのファイル形式へ変更する場合は、旧形式からの移行処理を用意する。
- PDFと画像は閲覧・共有用とし、再編集可能なプロジェクトファイルとは区別する。

## 9. テスト方針

| 種別       | 対象                               | 使用技術        | 方針                                             |

| 単体テスト | ゲージ計算、座標変換、データ更新   | Vitest          | 純粋関数と状態更新を中心に検証する               |
