# Knit Canvas 要件定義（プロトタイプ版）

更新日: 2026-09-01  
対象: セーターなどのカラーワーク（編み込み模様）を設計するための方眼エディター

## 1. プロダクト概要

Knit Canvas は、実際の編みゲージに合わせた方眼上へ色を置き、カラーワークのパターンを作成するアプリである。Apple Pencil、タッチ、マウスで、ドット絵を描くように1目ずつ編集できることを中核体験とする。

作成した1単位のパターンは、横方向へ連続配置したタイル表示で確認できる。印刷・PDF書き出しでは、方眼の編み図と5回分の横リピート完成イメージをA4用紙1枚にまとめる。

## 2. 想定ユーザーと利用場面

- セーター、ヨーク、フェアアイルなどの配色模様を考える編み手
- 実物を編む前に配色と横方向の連続性を確認したい人
- 印刷した編み図を手元に置いて制作したい人
- 将来的には、写真や手描きスケッチを編み図へ置き換えたい人

## 3. 用語

- **編み図**: 1マスを1目×1段として表す編集用方眼
- **実ゲージ**: 10cmあたりの目数・段数に基づく、実際の縦横比を反映した方眼
- **パターン**: 横方向へ繰り返す1単位のカラーワーク
- **パターンリピート**: 作成したパターンを横方向へタイル状に連続表示したもの

## 4. MVPの機能要件

### 4.1 方眼設定

- 方眼の横数（目数）と縦数（段数）を、それぞれ自由に変更できること
- 初期値は30目×30段とすること
- 現プロトタイプでは1〜200の範囲、1単位で変更できること
- 数を変更した際、表示方眼とパターンリピートが追従すること
- 本開発では、サイズ変更時に既存の描画を保持するか、確認して初期化するかを明示すること

### 4.2 ゲージ設定と表示

- 横ゲージを「10cmあたりの目数」、縦ゲージを「10cmあたりの段数」と明記すること
- 方眼は常に実ゲージ表示とし、通常方眼との切り替えは設けないこと
- 1目の横幅は `100 ÷ 10cmあたりの目数` mm とすること
- 1段の高さは `100 ÷ 10cmあたりの段数` mm とすること
- セルの縦横比へ上記の比率を反映すること
- 完成幅は `横の目数 ÷ 横ゲージ × 10` cm とすること
- 完成高さは `縦の段数 ÷ 縦ゲージ × 10` cm とすること
- ゲージ値と完成寸法を画面内に表示すること
- 印刷時にも分かるよう、ゲージをページ右下へ記載すること

### 4.3 方眼の表示仕様

- 1マスを1目×1段として表示すること
- 横線は1段ごとに実線で表示すること
- 5目・5段ごとに補助的な太線を表示すること
- 目数と段数は5、10、15…の切りのよい数字を基本として表示すること
- 終端が5の倍数でない場合は、終端の数値も識別できること
- 段数は下から上へ数えること
- 方眼が大きい場合はスクロールまたは適切な縮尺で全体を扱えること

### 4.4 描画操作

- 描画ツールは、現段階では鉛筆と消しゴムの2種類だけとすること
- 鉛筆では選択中の色を1マスへ配置できること
- 消しゴムではマスの色を消せること
- マウスを押したまま横・縦・斜めへ引くと、通過したマスへ連続して色を付けられること
- Apple Pencil、タッチ操作、マウスを同じポインター操作として扱えること
- 同じマスを通過した際に不要な処理を繰り返さないこと
- 少なくとも「元に戻す」を提供すること
- 全消去は誤操作を防ぐ確認または取り消し手段を持つこと

### 4.5 色糸パレット

- 最初に24色から色を選べること
- 選択中の色を視覚的に明示すること
- 選択色の名称または識別情報を表示すること
- 描画と同時に、パターンリピートへ色を反映すること
- 将来は毛糸ブランド、品番、ロット、独自色の登録へ拡張できる構造にすること

### 4.6 パターンリピート

- 編み図の上に「パターンリピート」領域を配置すること
- 説明文は「作成したパターンを横方向にタイル表示」など、用途が分かる表現にすること
- 1つのパターンを横方向へ連続表示すること
- 表示回数は3回・5回・8回から選択できること
- 初期表示は5回とすること
- 回数の切り替えUIは、横リピート完成イメージの下へ置くこと
- 方眼での編集内容をリアルタイムに反映すること
- リピートの継ぎ目が確認できること

### 4.7 画面領域のサイズ変更

- パターンリピート領域と編み図領域の境界をドラッグできること
- ユーザーがリピートを大きく見たい場合、リピート領域を拡大できること
- 反対に、編み図を広く使いたい場合は編み図領域を拡大できること
- 変更後も描画内容と表示状態を維持すること

### 4.8 A4 PDF・印刷

- 「書き出す」操作からA4縦向きの印刷画面を開けること
- 1ページ上部に、方眼線と段・目の番号を含むカラーワーク編み図を配置すること
- 1ページ下部に、少し縮小した5回分の横方向パターンリピートを配置すること
- 右下に、10cmあたりの目数・段数、方眼サイズ、完成寸法を記載すること
- 作成日または書き出し日を記載すること
- 背景色を含めて色が印刷されること
- 現プロトタイプではブラウザーの印刷機能から「PDFとして保存」する方式とすること
- 本開発では直接PDFを生成・ダウンロードする方式も検討すること

## 5. 画面構成

1. ヘッダー
   - ドキュメント名
   - 元に戻す
   - 書き出す
2. 左サイドバー
   - 方眼の横数・縦数
   - 10cmあたりの横ゲージ・縦ゲージ
   - 鉛筆・消しゴム
   - 24色の色糸パレット
3. 中央上部
   - パターンリピート
   - 横方向のタイル表示
   - 3回・5回・8回の切り替え
4. 中央下部
   - 実ゲージ比率の編集用方眼
5. 右サイドバー
   - 方眼サイズ
   - 使用色
   - 完成寸法
   - ゲージ情報

## 6. 非機能要件

- 描画中の反応が遅れず、一般的なiPadとPCで自然に線を引けること
- 30×30程度では即時更新し、最大設定時にも操作不能にならないこと
- タッチ操作時に描画とページスクロールが競合しないこと
- 色の選択状態を色だけに依存せず、枠線等でも示すこと
- キーボード操作やラベルを備え、基本的なアクセシビリティへ配慮すること
- 印刷結果が主要ブラウザーでA4 1ページに収まること
- 将来の保存形式に備え、方眼サイズ・ゲージ・パレット・各セルの色をデータとして分離すること

## 7. 現時点で対象外・将来機能

### 7.1 AIによる画像から方眼への変換

初期MVPからはいったん外す。ただし将来機能として以下を想定する。

- 写真または手描き画像をアップロードする
- AIまたは画像処理が輪郭、色、構図を判定する
- 指定した目数×段数へ縮小・量子化し、方眼へ落とし込む
- 24色またはユーザー指定色へ減色する
- 変換結果をプレビューし、強さ・色数・トリミングを調整する
- 最終結果は通常の鉛筆・消しゴムで修正できる
- 「写真をそのまま複製する」のではなく、「編めるパターンへ翻訳する」ことを目標にする

### 7.2 その他の将来候補

- プロジェクトの保存・読み込み
- 自動保存と復元
- やり直し（Redo）の完全実装
- ズーム、パン、全体表示
- パターン名やメモの編集
- 独自パレット、毛糸ブランド・品番との連携
- 使用色数・必要糸量の自動集計
- 複数パターンとバージョン管理
- クラウド同期、共有、共同編集
- SVG、PNG、直接PDF生成

## 8. 受け入れ条件（MVP）

- 任意の目数・段数と10cmゲージを入力すると、実ゲージ比率の方眼が表示される
- 24色から1色を選び、マウスまたはペンを押したまま動かすと、通過したマスが連続して塗られる
- 消しゴムで同様に連続消去できる
- 全ての段に実線があり、5目・5段ごとの目盛りを確認できる
- 編集内容が、方眼上部の横方向パターンリピートへ即時反映される
- リピート回数を3・5・8回へ変更でき、初期値は5回である
- リピート領域と編み図領域の境界を動かし、表示サイズを変更できる
- A4印刷で、上部に方眼の模様、下部に5回リピート、右下にゲージが表示される

## 9. 現在のHTMLプロトタイプの状態

`knit-grid-mock.html` は、依存ライブラリなしで開ける単一HTMLの操作モックである。主要な描画、24色パレット、実ゲージ方眼、横リピート、領域サイズ変更、印刷レイアウトを試せる。

本開発前に整理が必要な点:

- 保存・自動保存表示は永続化されていない
- ズームやRedoなど、一部の見た目上のボタンは本機能未実装
- 使用色の表示は動的集計へ変更が必要
- 方眼サイズ変更時の既存データ保持方針を決める必要がある
- PDFはブラウザー印刷を利用しており、直接生成ではない
- 大きな方眼、iPad、Apple Pencil、複数ブラウザーでの性能検証が必要

## 10. プロジェクト化の推奨方針

現在のHTMLを仕様確認用プロトタイプとして残し、本番版は段階的に構造化する。

1. Gitリポジトリを作成し、このHTMLと要件書を最初の資料として登録する
2. TypeScriptベースのWebアプリへ移行する
3. データ、描画ロジック、画面、印刷処理を分離する
4. IndexedDB等でローカル保存を実装する
5. PWA化し、iPadでもホーム画面から使えるようにする
6. MVPの操作検証後、AI画像変換を独立機能として追加する

推奨する主要データ項目:

```text
PatternProject
├─ name
├─ columns / rows
├─ stitchesPer10cm / rowsPer10cm
├─ palette[24]
├─ cells[row][column] = colorId | null
├─ repeatCount
└─ createdAt / updatedAt
```
